# Известные проблемы и ограничения

1. Ничего не запускалось в Dota. Использованные API (SetModifyGoldFilter, SetRuneEnabled,
   SetCreepSpawningEnabled, SetStartingGold и др.) вызываются через `Log.try` — отсутствующие будут в логе
   `[RIFT][WARN][API] missing ...`.
2. Dev-карта `dota`: на ней есть крипы/нейтралы/строения/Древние, если соответствующие API не отключат их;
   разрушение Древнего может завершить игру стандартной победой. Только для логики до появления карты арены.
3. Курьеры, скан, предметы на земле, передача предметов между игроками — ещё не настроены явно (этап B/E).
4. Магазин: включён universal shop mode; «магазин из любой точки» не реализован — на dev-карте покупка у
   фонтанов/магазинов команд, у custom-команд фонтанов нет. Нужна проверка (этап E).
5. Помощь не учитывает контроль без урона.
6. Только Phantom Assassin в выборе; направления ульты ещё не реализованы (этап C), т.е. сейчас PA — стандартная.
7. Локализация в UTF-8: если Dota покажет «кракозябры», конвертировать `addon_*.txt` в UTF-16 LE.
8. При дисконнекте блокировка передачи предметов не реализована.
9. На время выбора направления ульта блокируется `SetActivated(false)`. Пассивная native-ульта (крит PA)
   продолжает базовый эффект до выбора — это не эффект ветки; проверить в игре.
10. `direction_adapter` использует `SwapAbilities`/`StartCooldown`/`GetCooldown(level-1)` — поведение hotkey и
    tooltip после замены проверить в игре при первой реализованной ветке.
11. Пути частиц события (ping_world, aegis_timer) не проверены — OP-008. Без них событие работает, но хуже читается.
12. `MODIFIER_PROPERTY_PROVIDES_FOW_POSITION` у носителя может не раскрывать позицию врагам — надёжное раскрытие
    сделано периодическим `AddFOWViewer` для всех команд.
13. **БЛОКЕР.** Lua-модификаторы не регистрировались при LinkLuaModifier только на уровне файла `addon_game_mode.lua`
    («Attempted to create unknown modifier type»). Фикс-кандидат: повторная регистрация в `Activate()`; проверка —
    `rift_modtest` (печатает загрузку файла каждого модификатора и результат AddNewModifier).
    Сессия 8 (агент): определение таблиц модификаторов больше не зависит от глобального `class` (если он есть —
    используется, иначе обычная таблица); выдача модификаторов идёт через `engine/mods.lua`, который пишет
    `[RIFT][ERROR][MODS] failed to attach <имя>` при неудаче; статическая проверка `tools/check_mods.js`.
    Причина не подтверждена — ждём `rift_modtest` (OP-011).
14. Facets героев (например, PA «Methodical»: крит каждые N атак) меняют native-механику ульты. Политика facets
    для направлений не определена; до решения — проверять направления на facet по умолчанию.
15. Таланты, пересекающиеся с направлениями (PA `extra_daggers` +2 vs «+1 цель» магической ветки;
    SF `special_bonus_unique_nevermore_7` к Shadowraze), требуют branch-specific политики до перевода в implemented.
