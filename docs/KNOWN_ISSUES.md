# Известные проблемы и ограничения

1. Ничего не запускалось в Dota. Использованные API (SetModifyGoldFilter, SetRuneEnabled,
   SetCreepSpawningEnabled, SetStartingGold и др.) вызываются через `Log.try` — отсутствующие будут в логе
   `[RIFT][WARN][API] missing ...`.
2. Dev-карта `dota`: на ней есть крипы/нейтралы/строения/Древние, если соответствующие API не отключат их;
   разрушение Древнего может завершить игру стандартной победой. Только для логики до появления карты арены.
3. Курьеры, скан, предметы на земле, передача предметов между игроками — ещё не настроены явно (этап B/E).
4. Магазин: включён universal shop mode; «магазин из любой точки» не реализован — на dev-карте покупка у
   фонтанов/магазинов команд, у custom-команд фонтанов нет. Нужна проверка (этап E).
5. Помощь не учитывает контроль без урона.
6. PA в выборе как стандартный герой: обе ветки написаны (сессия 18), но `planned` до OP-020/021 — меню выбора у PA пока нет.
7. Локализация в UTF-8: если Dota покажет «кракозябры», конвертировать `addon_*.txt` в UTF-16 LE.
8. При дисконнекте блокировка передачи предметов не реализована.
9. На время выбора направления ульта блокируется `SetActivated(false)`. Пассивная native-ульта (крит PA)
   продолжает базовый эффект до выбора — это не эффект ветки; проверить в игре.
10. `direction_adapter` использует `SwapAbilities`/`StartCooldown`/`GetCooldown(level-1)` — поведение hotkey и
    tooltip после замены проверить в игре при первой реализованной ветке.
11. Пути частиц события (ping_world, aegis_timer) не проверены — OP-008. Без них событие работает, но хуже читается.
12. `MODIFIER_PROPERTY_PROVIDES_FOW_POSITION` у носителя может не раскрывать позицию врагам — надёжное раскрытие
    сделано периодическим `AddFOWViewer` для всех команд.
13. Lua-модификаторы: на СЕРВЕРЕ работают (OP-011, 2026-11-12). Остаётся «unknown modifier type» в канале General —
    вероятно клиентская VM. Сессия 9: регистрация добавлена в `addon_init.lua` (клиент+сервер), ждёт OP-012.
    Исходная запись: Lua-модификаторы не регистрировались при LinkLuaModifier только на уровне файла `addon_game_mode.lua`
    («Attempted to create unknown modifier type»). Фикс-кандидат: повторная регистрация в `Activate()`; проверка —
    `rift_modtest` (печатает загрузку файла каждого модификатора и результат AddNewModifier).
    Сессия 8 (агент): определение таблиц модификаторов больше не зависит от глобального `class` (если он есть —
    используется, иначе обычная таблица); выдача модификаторов идёт через `engine/mods.lua`, который пишет
    `[RIFT][ERROR][MODS] failed to attach <имя>` при неудаче; статическая проверка `tools/check_mods.js`.
    Причина не подтверждена — ждём `rift_modtest` (OP-011).
14. Facets героев (например, PA «Methodical»: крит каждые N атак) меняют native-механику ульты. Политика facets
    для направлений не определена; до решения — проверять направления на facet по умолчанию.
15. Таланты, пересекающиеся с направлениями (PA `extra_daggers` +2 vs «+1 цель» магической ветки;
    SF `special_bonus_unique_nevermore_7` к Shadowraze), требуют branch-specific политики до перевода в implemented.
16. `dota_launch_custom_game` не перезагружает уже загруженные `require`-модули: после правок Lua нужен полный
    перезапуск Workshop Tools (подтверждено оператором).
17. Глобальные переменные из `addon_game_mode.lua` не видны в `require`-модулях (свой scope) — общие данные держать
    в модулях (`rift/modifier_list.lua`).
18. ~~Пропала Refraction~~ — не дефект: в текущей версии Dota у TA нет Refraction (OP-013 повтор). Защита адаптера
    (лог раскладки, восстановление скрытых/удалённых способностей) оставлена как страховка.
19. В этой версии Dota Refraction нет в наборе TA, но данные способности в клиенте есть. Решение владельца
    (2026-11-12): Refraction как в Dota, без изменений — добавляется в базовый набор TA при появлении
    (`data/hero_kits.lua`, Q). Физическая ветка её не трогает; магическая заменяет её своей Q с переносом уровня.
    Частицы/звуки Refraction могут быть не прекешированы (не входит в набор героя) — проверить в OP-018.
20. SF magical: native Requiem сохранён целиком, поэтому его cooldown/мана — native (120/110/100), а не PD 110/100/90
    из ТЗ. Чтобы применить PD, нужна своя копия способности; пока не делалось.
21. SF magical: страх через `MODIFIER_STATE_FEARED` — движок должен сам уводить юнит; проверить в OP-017. Кольца
    запускаются по `MODIFIER_EVENT_ON_ABILITY_FULLY_CAST` (прерванный каст — без колец), автоматический Requiem при смерти
    отсекается проверкой «герой жив».
22. Для теста иммунитета нет dev-команды выдачи BKB/иммунитета манекену — добавить `rift_dummy_bkb` при необходимости.
23. Dev-манекен-герой на команде NEUTRALS для части проверок цели считался союзником (OP-015). Манекены теперь в
    свободной команде без игроков. Нейтральная команда для кристалла TA остаётся (его должны бить все).
24. PA physical: частица духа — временная (Death Pulse Necrophos), путь не проверен; образ духа Grimstroke не подобран.
    Удар духа не промахивается по уклонению (это не атака) — решение по умолчанию, владельцем не подтверждено.
25. PA magical: кинжал — своя способность, не native: талант «+2 кинжала» не действует; Shard/Scepter-эффекты
    native-кинжала (если есть) не воспроизводятся. Кулдаун и мана читаются со скрытого native-кинжала.
26. PA: обычные улучшения под направления (12 на героя по BRIEF §12) ещё не добавлены.
27. Манекен теперь бессмертен: проверки «цель умерла» делать через `rift_clear_dummies` или второго игрока.
