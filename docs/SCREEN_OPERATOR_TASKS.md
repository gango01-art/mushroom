# Задания экранному оператору

Формат: ID, цель, статус (pending / in_progress / blocked / verified), инструмент, пути, шаги,
критерий успеха, что записать, зависимость. Результаты дописывать под заданием (раздел «Отчёт»)
— агент читает их в начале каждой сессии. Не выполнять Workshop-публикацию.

---
## OP-001 — Обследовать установку Dota 2 и Workshop Tools
- Статус: pending
- Инструмент: Steam, Проводник Windows.
- Шаги:
  1. В Steam: Библиотека → Dota 2 → Управление → Просмотреть локальные файлы. Записать полный путь.
  2. Проверить, установлено ли DLC «Dota 2 Workshop Tools» (Свойства → DLC). Если нет — сообщить владельцу (установка бесплатная, но решение владельца).
  3. Проверить существование папок `<путь>\game\dota_addons` и `<путь>\content\dota_addons`.
  4. Проверить, где лежит клон репозитория `mushroom` на этой машине (или что его нет).
- Успех: известны путь Dota, наличие Tools, наличие обеих папок, путь репозитория.
- Записать: эти 4 факта + версию Dota (главное меню / консоль `version`, если удобно).
- Зависимость: блокирует OP-002. Агент продолжает чистую логику без этого.

## OP-002 — Подключить addon и запустить до ACTIVE (сценарий 1)
- Статус: pending (после OP-001)
- Инструмент: PowerShell, Dota 2 Workshop Tools, консоль Dota.
- Пути: репо `<repo>\game` → `<dota>\game\dota_addons\rift_arena`; `<repo>\content` → `<dota>\content\dota_addons\rift_arena`.
- Шаги:
  1. `git pull` в клоне репозитория (ветка `claude/pensive-curie-zvybbg`).
  2. `powershell -ExecutionPolicy Bypass -File tools\link_addon.ps1 -WhatIf` → прочитать вывод; затем без `-WhatIf`.
  3. Запустить Dota 2 Workshop Tools (через Steam: «Запустить Dota 2 — Tools» или как предлагает текущий интерфейс; сначала осмотреть интерфейс). Выбрать addon `rift_arena`.
  4. Открыть консоль (кнопка/клавиша консоли в Tools), выполнить `dota_launch_custom_game rift_arena dota`.
  5. Дождаться экрана лобби → выбор героя (должен быть доступен только Phantom Assassin) → подготовка 10 с → бой.
  6. В бою выполнить `rift_status`.
- Успех: сверху по центру панель со стадией «Бой» и таймером, идущим от 18:00 вниз; справа таблица; в консоли строки `[RIFT][INFO][STATE] PREPARATION -> ACTIVE` и вывод `rift_status`; уровень героя 3, золото около 1200 в начале.
- Записать: ВСЕ строки консоли с `[RIFT]`, любые красные/жёлтые ошибки Lua/Panorama/KV (дословно), скриншот HUD.
- Зависимость: блокирует проверку этапов A/B в игре.

## OP-003 — Цикл матча с ботом/вторым игроком (сценарии 2, 8)
- Статус: pending (после OP-002)
- Шаги:
  1. Запустить как в OP-002. Если есть второй человек — пригласить. Иначе попробовать консоль `dota_create_fake_clients 1` до выбора героя (engine-команда; если её нет в текущей версии — записать это). Тестовый клиент не заменяет реального игрока.
  2. В бою: `rift_kill 1` (убить героя игрока 1 без убийцы) — проверить, что очки никому не начислены.
  3. Нанести урон второму герою и убить его. Проверить +3 очка, золото/опыт, респаун через ~6 с в другой точке, щит после появления.
  4. `rift_skip 1070` → дождаться 18:00. Ожидается конец матча и финальный экран с причиной.
  5. Повторить запуск; дать обоим по одинаковому счёту (`rift_addscore 0 3`, `rift_addscore 1 3`), `rift_skip 1075` → ожидается «Овертайм» 2:00; затем `rift_addscore 1 1` → победа игрока 1, причина «Первое очко в овертайме».
- Успех: каждое ожидаемое поведение наблюдается; одно завершение матча.
- Записать: строки `[RIFT]` консоли, скриншоты финального экрана, отклонения от ожидаемого.

## OP-004 — Выгрузить реальные значения способностей Phantom Assassin
- Статус: pending (после OP-002; можно в том же запуске)
- Инструмент: консоль Dota Workshop Tools (запуск как в OP-002).
- Шаги:
  1. В бою (герой PA выбран) выполнить `rift_dump_hero 0`.
  2. Скопировать весь вывод строк `[RIFT][DUMP]` и строк под ними (значения способностей).
  3. Если команда напечатала только заголовки без значений — записать это.
- Успех: в отчёте есть имена всех способностей PA (слоты, max level, тип) и их значения (особенно у ультимейта и Stifling Dagger).
- Записать: весь вывод (можно файлом `console.log` из папки игры, если включено логирование).
- Зависимость: блокирует реализацию направлений PA в движке (этап C ч. 2): без этого агент не будет угадывать
  ключ множителя крита и текущее устройство Coup de Grace. Чистая логика продолжается без этого.

## OP-005 — Улучшения в игре: предложения, выбор, эффекты
- Статус: pending (после OP-002)
- Инструмент: Dota 2 Workshop Tools, консоль.
- Шаги:
  1. Запуск как в OP-002, дойти до боя. Через 30 с боя внизу экрана над панелью способностей должна появиться панель «Выберите улучшение» с 1–3 карточками (редкость «Обычное»), таймером 45 с, кнопкой «Свернуть».
  2. Нажать «Свернуть» → должна остаться кнопка «Улучшение (1)»; нажать её → панель снова видна с теми же карточками.
  3. Запомнить броню/урон/HP героя, выбрать карточку. Ожидается: панель исчезла, слева в «Сборка» появилась строка улучшения с рангом 1/N, характеристика героя изменилась на число из карточки.
  4. Быстро нажать карточку дважды на следующем предложении (`rift_offer_now 0` создаёт его сразу) — эффект должен примениться один раз.
  5. На ещё одном предложении (`rift_offer_now 0`) ничего не выбирать 45 с → должен примениться первый вариант (в консоли `by=timeout`).
  6. `rift_upgrades 0` — вывод сборки и seed.
  7. Убить героя (`rift_kill 0`) и дождаться возрождения: улучшения и характеристики сохраняются.
- Успех: все ожидания шагов 1–7 наблюдаются; нет ошибок Panorama/Lua.
- Записать: строки `[RIFT]` консоли, скриншоты панели выбора (1920×1080 и, если возможно, 2560×1440), какие характеристики изменились и на сколько, любые ошибки дословно.
- Зависимость: этап C ч. 2b (направления PA) можно писать параллельно; результаты нужны до перевода в «проверено».
